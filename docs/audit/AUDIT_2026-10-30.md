## 1. Ringkasan eksekutif

Kondisi umum: fondasi keamanan data KUAT dan terverifikasi dinamis — semua tulis
lewat RPC `SECURITY DEFINER` (auth/role/ownership di DB), RLS SELECT-only, IDOR
ditolak (404 tanpa bocor), daily-cap 429 benar, replay confirm ditolak
`not_reserved`, student tak bisa approve tenant / baca admin_report (0 rows).
Namun ALUR INTI PUTUS di UI: QR pickup tidak render (terbukti dinamis), dan
fallback manual scan tak terjangkau saat kamera mati — tenant tak bisa konfirmasi
tanpa QR. Typecheck lolos, 41/41 test lolos, lint gagal (2 error script dev).

5 temuan paling penting:
1. UI-01 (Critical, dinamis CONFIRMED): QR pickup tidak tampil di `/pesanan/[orderId]`
   berstatus reserved — komponen return undefined (screenshot bukti).
2. UX-07 (High, dinamis CONFIRMED): form "kode manual" scan tak pernah muncul saat
   kamera diblokir/tak ada — loop error→reset→error; konfirmasi manual mustahil.
3. SEC-01 (Medium, dinamis CONFIRMED via header): tanpa security headers apa pun
   (hanya `X-Powered-By`), termasuk di halaman QR/bayar.
4. SEC-10 (Medium, dinamis CONFIRMED): `impact_summary.posted` bocor ke SEMUA
   user login (812 terlihat sebagai student) — subquery tanpa guard admin.
5. SEC-02 (Medium): tanpa rate limiting server-side (OTP, /api/orders, apply, scan).

Urutan perbaikan:
1. UI-01 + UX-07 (alur inti putus; keduanya < 1 hari).
2. SEC-01 headers + SEC-10 tambah guard `posted` (cepat, migrasi kecil).
3. SEC-02 rate limit + SEC-04 minimasi PII buyer.
4. BIZ-01 slot mati, BIZ-02/03 kebijakan peran tertulis.

## 4. Detail temuan

### UI-01 — QR tidak tampil (Critical, Confirmed D)
Bukti dinamis: order reserved `a1706b6b…` (dibuat saat audit) render tanpa
`#qr-heading`, tanpa teks "Tunjukkan ke", tanpa `role=alert` (token ada, jadi
bukan cabang null) — `qr-panel.tsx:33` JSX tanpa `return`. Dampak: mahasiswa tak
bisa tunjukkan QR; konfirmasi pickup mustahil via jalur normal. Rekomendasi:
tambah `return`; test render saat token ada. Estimasi S.
Bukti: `evidence/student-order-detail-no-qr.png`.

### UX-07 — Kode manual scan tak terjangkau (High, Confirmed D)
Saat kamera diblokir/tak ada: phase=error → tombol "Masukkan kode manual" →
`reset(true)` → phase=scanning + `manualOpen` → `<Scanner>` mount → `onCameraError`
lagi → kembali error. Form manual (hanya di cabang scanning) tak pernah menetap;
2× klik tak hasilkan `<input>`. Perangkat tanpa kamera = tenant tak bisa
konfirmasi sama sekali (padahal token plaintext disediakan di detail order untuk
jalur ini). Rekomendasi: render form manual juga di cabang error (atau
`showManual` → form inline, bukan via reset). Estimasi S.
Bukti: DOM `INPUTS: []` + `scanner-client.tsx:194-223 vs 334-343`.

### SEC-10 — `posted` bocor (Medium, Confirmed D)
Sebagai student: `admin_report` → 0 rows (aman), `impact_summary` → 1 baris
dengan agregat 0 TAPI `posted: 812` (volume global real). Penyebab: subquery
`posted` tanpa `EXISTS (…role='admin')` (hanya outer WHERE yang diguard).
Dampak: enumerasi volume platform oleh user mana pun. Rekomendasi: tambah guard
yang sama di subquery `posted`. Estimasi S.

### SEC-01 — Security headers kosong (Medium, Confirmed)
`next.config.ts` hanya berisi `images.remotePatterns` + `allowedDevOrigins`.
Tidak ada `headers()` → tidak ada CSP, `frame-ancestors`, HSTS, `X-Content-Type-Options`,
`Referrer-Policy`, `Permissions-Policy`. Dampak: clickjacking di halaman QR/bayar
di tempat, MIME-sniffing, paresial. Eksploitasi butuh situs jahat + korban
tertipu (kemungkinan sedang). Rekomendasi (diff hanya di laporan):
tambah `async headers()` dengan `frame-ancestors 'self'`, `X-Content-Type-Options:
nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Permissions-Policy: camera=(self)` (halaman scan butuh kamera!), HSTS bila domain
tetap HTTPS, dan CSP bertahap (mulai `default-src 'self'`, allow supabase +
google auth). Estimasi: S.

### SEC-02 — Rate limiting server-side tidak ada (Medium, Confirmed)
Grep `ratelimit|throttle|upstash` di `src supabase next.config.ts package.json`:
kosong. Satu-satunya rem adalah cooldown kirim-ulang 30 dtk di klien
(`email-sign-in.tsx` `RESEND_COOLDOWN_S`) — mudah dilewati via API langsung.
Dampak: spam OTP (biaya email + enumerasi), brute force order/kuota, spam
pendaftaran tenant, tebak QR (ruang 2^122 — tidak praktis, tapi confirm endpoint
tetap perlu rem). Rekomendasi: rate limit di Supabase Auth dashboard (OTP/email)
+ pembatas di `POST /api/orders` dan `apply_as_tenant` (mis. fixed-window per
user/IP via tabel atau edge middleware), captcha/turnstile di `/masuk` bila spam
terjadi. Estimasi: M.

### BIZ-01 — Slot pickup mati (Medium, Confirmed)
`POST /api/orders` selalu kirim `p_slot_start: null, p_slot_end: null`; `order-form.tsx`
tidak punya pemilih jadwal. Cabang validasi slot di `place_order` (invalid slot,
slot past expiry, before release) tidak pernah tereksekusi. Dampak: logika tak
teruji membusuk; bila UI slot ditambah nanti tanpa sadar, perilaku belum tentu benar.
Rekomendasi: putuskan — (a) hapus parameter slot dari RPC + pesan error, atau
(b) tambah UI slot + test. Estimasi: S–M.

### SEC-03 — Celah guard proxy + klarifikasi dinamis (Low, Confirmed D)
`isProtected` (`proxy.ts:55-61`) tidak mencakup `/akun/*`, `/notifikasi`,
`/api/*`. Verifikasi dinamis: `/akun/pengaturan` dan `/notifikasi` anonim → 307
ke `/masuk?next=…` (via page-level `requireRole`) — backstop bekerja. Dampak
rendah, tetap Low defense-in-depth: setiap halaman baru yang lupa `requireRole`
langsung terbuka. Rekomendasi: balik logika — lindungi default (kecuali daftar
publik `/`, `/cara-kerja`, `/masuk`, `/auth/*`, aset). Estimasi: S.
Bypass-check dinamis (read-only, server dev): `/KATALOG`, `/ADMIN`, `/Tenant`,
`/PESANAN` → 404 (tidak lolos); `/katalog/`, `/api/orders/`, `//katalog` → 308
normalisasi ke path protek; `GET/PUT/DELETE/PATCH /api/orders` → 405 (hanya
POST); `/auth/callback` tanpa code → 307 masuk?error. Tidak ada celah
trailing-slash/case/method.

### SEC-04 — PII berlebih (Low, Confirmed)
`profiles_read … to authenticated using (true)` — SEMUA user login bisa membaca
`email, full_name, avatar_url` SEMUA user. `tenant_order_detail` mengembalikan
`buyer_name = full_name ?? email` + agregat riwayat buyer (total pickup/cancel).
Dampak: enum user + profiling pembeli oleh tenant; email buyer terekspos rutin.
Rekomendasi: batasi `profiles` select (hanya self + kolom minim untuk keperluan
tenant, mis. nama samaran), tampilkan nama depan/inisial saja ke tenant.
Estimasi: M (perlu migrasi RLS + ubah RPC).

### SEC-05 — Token pickup plaintext di sisi tenant (Low, Confirmed)
`tenant/pesanan/[id]/page.tsx` merender `Kode pickup: <span mono>{token}</span>`
+ `CopyTokenButton` (butuh clipboard). Niatnya sah (manual entry bila kamera rusak).
Dampak: shoulder-surfing/screenshot; token + papan info = pickup oleh orang salah
(tapi tetap butuh kehadiran fisik + konfirmasi tenant pemilik, dan token satu-pakai
via cek status). Rekomendasi: sembunyikan default (klik-untuk-tampil, auto-hide),
masking parsial, audit log `confirm_pickup`. Estimasi: S.

### BIZ-02 — Admin exempt daily cap (Low, Confirmed)
`daily_cap.sql`: `if not exists (… role='admin')` → cek kuota dilewati untuk admin.
Mungkin disengaja (testing), tapi tak terdokumentasi; admin bisa borong stok langka
dan merusak metrik `impact_summary`. Rekomendasi: dokumentasikan atau samakan cap;
bila admin perlu test, gunakan peran student dummy. Estimasi: S.

### BIZ-03 — Tenant bisa memesan tenant lain (Low, Confirmed)
RPC hanya menolak `tenant cannot order own portion`. Tenant A boleh memesan stok
Tenant B — bersaing dengan mahasiswa yang menjadi target program. Bisa disengaja
(tenant juga warga kampus), tapi tak tertulis di brief/BR. Rekomendasi: putuskan +
tulis di `docs/decisions.md`/FAQ; bila dibatasi, tambah cek role di `place_order`.
Estimasi: S.

### BIZ-04 — Restore kuota tanpa pagu (Low, Likely)
`cancel_order`/`tenant_cancel_order` melakukan `quantity_remaining + qty` tanpa
`LEAST(…, quantity_posted)`. Ada CHECK `quantity_remaining <= quantity_posted`
— pembatalan ganda/konkuren akan meledak jadi 500 mentah, bukan pesan ramah.
Status guard (`not_reserved`) + `FOR UPDATE` membuat jarang terjadi; dua cancel
paralel (2–5 request, sesuai batas aman audit) perlu verifikasi manual dengan data
dummy. Rekomendasi: guard idempotensi + pesan ramah + clamp. Estimasi: S.

### BIZ-05 — Batas hari WIB via toLocaleString (Info, Confirmed)
`katalog/page.tsx` + `admin/page.tsx` menghitung awal hari WIB dengan
`new Date(new Date().toLocaleString("en-US", {timeZone:"Asia/Jakarta"}))`.
Berfungsi, tapi rapuh (locale/parse) dan diduplikasi. Rekomendasi: helper bersama
`dayBoundsWIB(date)` di `src/lib/domain` + unit test; DB tetap sumber kebenaran
(RPC daily cap sudah benar pakai `at time zone 'Asia/Jakarta'`). Estimasi: S.

### UI-02 — Lint gagal (Low, Confirmed)
`bun run lint`: 2 error di `scripts/gen-link.ts` (non-null assertion service-role,
string concat) + warning `useExhaustiveDependencies` di `site-header.tsx:26`.
Typecheck lolos, test 41/41 lolos. Rekomendasi: perbaiki/ kecualikan script dev
dari biome atau rapikan; putuskan `pathname` dep yang tak terpakai. Estimasi: S.

### UI-03 — Matcher proxy boros (Low, Confirmed)
`src/proxy.ts:9` hanya mengecualikan `svg|png|jpg|ico` — `gif/webp/avif/woff2`
tetap memicu refresh sesi Supabase (2× `getUser` per request). Dampak: latensi
aset. Rekomendasi: samakan pola pengecualian aset Next default. Estimasi: S.

### SEC-06 — CSRF (Info, Needs-manual-check)
Server actions + cookie auth tanpa token CSRF eksplisit; Next RSC mengandalkan
SameSite + header `Next-Action`. Perlu verifikasi manual flag cookie Supabase
(`SameSite=Lax`, `Secure`, `HttpOnly`) di environment prod + uji cross-origin POST
dari localhost. Tidak dilaporkan sebagai fakta.

### SEC-07 — Set-Cookie manual di callback (Info, Likely)
`auth/callback/route.ts:36-46` merakit string cookie manual dari opsi Supabase.
Flag diteruskan bila ada, tapi rapuh terhadap perubahan opsi (mis. `partitioned`,
`maxAge` vs `expires`). Rekomendasi: gunakan `NextResponse` cookie API
(`response.cookies.set`) agar serialisasi ditangani framework. Estimasi: S.

### SEC-08 — CVE glob via OpenNext (Info, Confirmed)
`bun audit`: 1 High — `glob >=10.2.0 <10.5.0` command injection via `-c/--cmd`
(`GHSA-5j98-mcp5-4vw2`), transitif dari `@opennextjs/cloudflare`. Jalur: CLI
build/deploy, bukan runtime aplikasi. Rekomendasi: `bun update` terkontrol +
catat di `docs/decisions.md` (jangan ubah lockfile dalam audit ini). Estimasi: S.

### SEC-09 — Service-role + OTP di stdout (Info, Confirmed)
`scripts/gen-link.ts:16` mencetak OTP email ke console dan membaca
`SUPABASE_SERVICE_ROLE_KEY` via non-null assertion. Ini script dev/seed, bukan
runtime — tapi siapa pun dengan akses repo + env bisa mintakan link. Rekomendasi:
jangan commit script berisi pemakaian service-role tanpa guard env, redact output,
hapus file bila tak dipakai. Secret aktif tidak ditemukan di repo/riwayat (grep
`sk_live|eyJ|supabase.co` bersih kecuali placeholder).

### IT-01 — File liar di repo (Low, Confirmed)
Root berisi `STDOUT`, `body.json`, `headers.txt`, `nul`, `regions.json`,
`scripts/shot-*.py`, `scripts/gen-link.ts`, folder `docs/siera-ref` dsb
