# BUG-2026-10-28T122802: 8 email seed 500 di semua jalur Auth, server-side

## Problem

- Aktual: `bun run seed:auth Porsi123!` gagal di `admin.auth.admin.createUser`
  dengan `500 Database error checking email` untuk 8 dari 9 email seed
  (semua kecuali `sinta@student.ac.id`, yang sukses dibuat: id `838d66cb…`).
  Login `/masuk` untuk 8 email itu: `500 Database error querying schema`.
- Harap: 9 akun seed bisa login email+password dengan role benar.
- Terkait: BUG-2026-10-28T120000 (seed tanpa `auth.users`). Fix repo
  (`scripts/seed-auth.ts` + `supabase/reseed_tenants.sql`) sudah benar dan
  `bun run check` hijau, tapi eksekusi seed mentok di error ini.
- Repro: `signInWithPassword({email: "rafi@student.ac.id", password: "x"})`
  → 500; email tak-ada → 400 normal; email fresh → createUser OK.

## Root Cause Analysis

- Matriks probe (semua konsisten, satu pola):
  1. `admin.listUsers({perPage:5})` OK (`total=15`); `{perPage:100}` dan
     page 2–3 → `500 Database error finding users`. Page 4 kosong (`n=0`).
     Artinya 1+ row rusak di offset 5–9 hasil scan berurutan.
  2. `admin.createUser` email fresh → OK (kontrol lolos, jadi service key +
     network + API path sehat). Email seed yang sudah ada di `profiles`
     tapi tanpa `auth.users` → `500 Database error checking email`.
  3. `anon.signUp` email seed rusak (`warteg@…`) → `500 Database error
     finding user`. Jadi bukan cuma Admin API — jalur publik pun pecah
     saat lookup/insert email itu.
  4. `anon.signIn` 9 email seed (password salah sengaja): 8 email →
     `500 Database error querying schema`; hanya `sinta@student.ac.id` →
     `400 Invalid login credentials` (lookup sehat). Pola biner sempurna:
     8 rusak / 1 sehat, berkorelasi dengan riwayat: 8 email itu pernah
     diinsert mentah ke `profiles` + dipakai percobaan `createUser`
     ber-`id` placeholder yang gagal; `sinta@…` tak pernah dicoba saat itu.
  5. Query `profiles` (service_role): 8 email rusak ADA sebagai row yatim
     (id acak dari trigger/signup parsial), `sinta@…` = id asli baru.
     Tak ada hook Auth custom aktif (`config.toml`: before_user_created /
     custom_access_token masih komentar), mailer SMTP tak dikonfigurasi
     (bukan penyebab — error terjadi sebelum kirim email).
- Kode repo tak tersentuh: migrasi `profiles`/`handle_new_user`/`guard`
  sehat (email fresh end-to-end OK termasuk trigger), RLS `profiles_read`
  hanya SELECT untuk authenticated (tak ada policy yang menyentuh skema
  `auth`). Error berasal dari dalam query skema `auth` milik Supabase
  (`checking email` / `finding user` / `querying schema`) — di luar
  jangkauan migrasi/repo. Kemungkinan sisa state korup: identitias
  parsial/duplikat untuk 8 email itu di tabel internal `auth`
  (akibat percobaan create ber-id placeholder + profile yatim), yang
  hanya pemilik project bisa lihat/bersihkan via dashboard/SQL.
- Security impact: LOW. No exploit path — error 500 generik tanpa bocor
  data; service key tetap server-side; akun dev-only.
- Risk: Medium (butuh aksi manual di dashboard hosted oleh pemilik project).
