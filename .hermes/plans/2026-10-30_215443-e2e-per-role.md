# E2E per-role: guest → student → tenant → admin (Playwright + MCP)

## Goal

Satu perintah menjalankan E2E 4 role di `localhost:3001`, tiap role 1 file spec independen: guest browsing, student pesan+QR, tenant posting+scan, admin moderasi+laporan.

## Current context / assumptions

- Stack: Next.js 16 App Router (`src/`), Supabase hosted (Auth+Postgres), Biome, Vitest (`bun run test`). Belum ada Playwright di repo.
- Login UI hanya Google + magic link (`signInWithOtp`) — keduanya mustahil headless. Seed (`bun run seed:auth <pw>`) membuat 9 akun email+password valid di Auth (1 admin, 6 tenant, 2 student, `src/lib/domain/seed-accounts.ts`) + `bun run db:seed` mengisi 16 menu, 16 porsi segar, 3 order contoh.
- Karena password terset di Auth, E2E login lewat `signInWithPassword` via API lalu injeksi cookie sesi — bukan lewat UI.
- App baca sesi via `@supabase/ssr` (cookie `sb-<project-ref>-auth-token`, format JSON array `[access, refresh]` base64). Jangan pakai localStorage.
- Rute per role:
  - guest: `/` (landing), `/cara-kerja`, `/katalog` (redirect `/masuk` bila anonim? katalog publik — verifikasi saat implementasi), `/masuk`.
  - student: `/beranda`, `/katalog`, `/katalog/[portionId]`, `/pesanan`, `/pesanan/[orderId]` (QR), `/profil`, `/akun/*`.
  - tenant: `/tenant` (dasbor), `/tenant/menu`, `/tenant/porsi/baru`, `/tenant/pesanan`, `/tenant/pesanan/[id]`, `/tenant/scan` (kamera tak ada di CI → pakai input kode manual scanner, bukan scan kamera), `/tenant/profil`.
  - admin: `/admin` (dampak), `/admin/tenant` (setuju + visibilitas).
- Server MCP `playwright` aktif di sesi ini (59 tools). Implementer memakainya untuk eksplorasi selector + verifikasi visual, bukan sebagai pengganti spec repo.
- Dev server: `bun run dev -- --port 3001` harus jalan sebelum spec.
- Data sensitif waktu: porsi punya jendela jual 120–240 mnt. Spec yang butuh porsi segar harus buat sendiri via UI tenant (nama menu unik per run, mis. `E2E <timestamp>`), jangan bergantung porsi seed yang bisa kedaluwarsa.

## Architecture / proposed approach

Repo `tests/e2e/` berisi `playwright.config.ts`, `global-setup.ts` (login 4 role → `playwright/.auth/*.json`), `helpers.ts` (buat menu+porsi via UI/API), dan 4 spec. Tiap spec `test.use({ storageState })` role-nya sendiri, independen, cleanup data yang ia buat. MCP Playwright dipakai saat development untuk menemukan selector stabil (`browser_snapshot`) dan bukti visual (`browser_screenshot`).

### 2. `global-setup.ts` — login API → cookie file. Buat `tests/e2e/global-setup.ts`:

```ts
import { writeFileSync, mkdirSync } from "node:fs";
import { createClient } from "@supabase/supabase-js";

const URL = process.env.NEXT_PUBLIC_SUPABASE_URL!;
const ANON = process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!;
const PW = process.env.SEED_PASSWORD!; // sama dengan argumen seed:auth
const REF = new URL(URL).hostname.split(".")[0];

const ACCOUNTS = {
  admin: "admin1793198479@yopmail.com",
  tenant: "warteg1793198479@yopmail.com",
  student: "rafi1793198479@yopmail.com", // cek nama persis di seed-accounts.ts
} as const;

async function login(email: string) {
  const sb = createClient(URL, ANON, { auth: { persistSession: false } });
  const { data, error } = await sb.auth.signInWithPassword({ email, password: PW });
  if (error || !data.session) throw new Error(`login gagal ${email}: ${error?.message}`);
  const value = Buffer.from(
    JSON.stringify([data.session.access_token, data.session.refresh_token]),
    "utf-8",
  ).toString("base64");
  return [{ name: `sb-${REF}-auth-token`, value: `base64-${value}`, domain: "localhost", path: "/" }];
}

export default async function () {
  mkdirSync("tests/.auth", { recursive: true });
  for (const [role, email] of Object.entries(ACCOUNTS)) {
    const cookies = await login(email);
    writeFileSync(`tests/.auth/${role}.json`, JSON.stringify({ cookies, origins: [] }));
    console.log(`auth ok: ${role}`);
  }
}
```

Verifikasi: `SEED_PASSWORD=<pw> bunx playwright test --list` tidak error + file `tests/.auth/*.json` terisi. Catatan: format cookie `base64-...` adalah konvensi `@supabase/ssr`; bila login gagal di step berikutnya, dump cookie lalu cocokkan dengan DevTools → Application → Cookies setelah login manual.

### 5. `tests/e2e/tenant.spec.ts`

Alur: `/tenant` dasbor angka terlihat → `/tenant/menu` tambah menu unik `E2E <Date.now()>` + harga → `/tenant/porsi/baru` posting porsi menu tsb → muncul di dasbor → `/tenant/scan` pakai **input kode manual** (bukan kamera) untuk order yang dibuat via API sebagai student → status jadi diambil.

Setup order scan: buat via `supabase-js` dengan sesi student (ambil token dari `global-setup`? simpan juga token mentah di `tests/.auth/student.token.json`) lalu `rpc place_order`. QR/kode manual: ambil `pickup_token` dari tabel orders via service key? DILARANG service key di test? Service key di server-side script test lokal = kredensial dev, bukan client code — boleh, simpan di `.env.local`, jangan commit.

Edge: posting dengan harga diskon ≥ harga normal → error validasi tampil; scan kode salah → pesan error tampil.

### 6. `tests/e2e/admin.spec.ts`

Alur: `/admin` angka dampak tampil → filter rentang → unduh CSV (tunggu event download) → `/admin/tenant` setujui pendaftar (bila ada; bila kosong, skip eksplisit) → toggle sembunyi/tampil satu tenant → verifikasi di `/katalog` (sesi guest/incognito context baru) porsi tenant tsb hilang/muncul.

## Tests / validation

Siklus per spec (adaptasi TDD untuk app yang sudah jadi):
1. Tulis 1 test → `bunx playwright test -c tests/e2e/playwright.config.ts -g "<nama>"` → MERAH (selector salah / alur belum cocok).
2. Perbaiki selector dengan bukti MCP: `browser_snapshot` pada halaman itu, bukan tebak-tebakan.
3. HIJAU → screenshot bukti (`browser_screenshot`) untuk 1 alur kritis per role → commit.
4. Ulangi per test berikutnya. Dilarang menulis 4 file sekaligus lalu debug massal.

## Risks, tradeoffs, and open questions

- **Cookie format rapuh**: bila `@supabase/ssr` upgrade, format `base64-` bisa berubah. Mitigasi: step 2 mencetak `auth ok`; bila semua spec 307 ke `/masuk`, periksa ulang format vs DevTools.
- **Magic link/Google tidak bisa E2E**: keputusan sadar — login UI tidak diuji; yang diuji alur pasca-login. Cantumkan di README test.
- **Waktu**: porsi kedaluwarsa di tengah run (jendela 120–240 mnt). Tenant spec membuat porsi sendiri tepat sebelum dipakai; jangan share porsi antar spec file (Playwright default paralel per file).
- **Kamera**: tidak ada di CI/headless → scan selalu lewat kode manual. Alur kamera fisik tetap manual QA.
- **Data kotor**: tenant spec membuat menu `E2E *` — tambahkan step cleanup (hapus menu via UI) di akhir spec; bila gagal di tengah, dokumentasikan cara bersih manual (`db:seed` ulang? TIDAK — seed mengisi ulang demo, bukan membersihkan; catat query hapus di plan eksekusi).
- **Open**: email student kedua + 5 tenant lain belum dipakai — cukup 1 akun per role untuk v1. `SEED_PASSWORD` dari mana diambil CI? Lokal saja (`.env.local`, git-ignored); belum ada CI server.
- **Tradeoff MCP**: 59 tools tersedia tapi spec repo harus mandiri (`@playwright/test` biasa) agar bisa jalan tanpa sesi Hermes. MCP hanya untuk development/eksplorasi.
